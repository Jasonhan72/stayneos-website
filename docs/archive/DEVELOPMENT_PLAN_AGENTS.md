## 一、Blueground 参考页面工作量评估

### 1.1 页面复杂度分级标准

| 级别 | 复杂度 | 工时估算 | 特征 |
|------|--------|----------|------|
| **L1** | 简单 | 4-8小时 | 静态内容页，2-3个Section，无复杂交互 |
| **L2** | 中等 | 1-2天 | 多Section页面，表单组件，基础动画 |
| **L3** | 复杂 | 3-5天 | 多模块页面，地图集成，复杂交互状态 |
| **L4** | 高复杂 | 1-2周 | 完整功能系统，数据库集成，第三方API |

## 三、技术实现建议

### 3.1 复用组件清单

基于现有 landlords 和 corporate 页面，可复用：

```
components/
├── layout/
│   ├── Section.tsx          # 区块容器
│   └── Container.tsx        # 内容容器
├── ui/
│   ├── Button.tsx           # 按钮组件
│   ├── Card.tsx             # 卡片组件
│   ├── Form/                # 表单组件
│   │   ├── Input.tsx
│   │   ├── Select.tsx
│   │   └── Textarea.tsx
│   └── StepIndicator.tsx    # 步骤指示器（流程图用）
```

### 3.2 新增组件需求

| 组件 | 用途 | 复杂度 |
|------|------|--------|
| `CooperationCard` | 合作模式卡片 | L1 |

| `RequirementList` | 房源要求列表 | L1 |
| `BenefitGrid` | 卖点网格 | L1 |

## 四、风险评估

### 4.1 潜在风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 翻译质量 | 中 | 提前准备翻译稿，预留审核时间 |
| 表单后端未就绪 | 高 | 先用静态表单，后续对接API |
| 地图API成本 | 低 | 使用 Mapbox 免费额度 |
| 设计审核延迟 | 中 | 每日同步，快速迭代 |

### 4.2 依赖项

- [ ] 品牌素材（Logo、图片）
- [ ] 经纪人合作政策文档
- [ ] 社区数据（多伦多各区域信息）
- [ ] 表单提交后端API
